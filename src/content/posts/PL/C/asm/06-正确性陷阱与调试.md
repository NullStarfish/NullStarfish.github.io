内联汇编最危险的故障模式是：`-O0` 正常，`-O2`、换一个调用点或稍微改动周围 C 代码就
出错。这通常不是优化器“优化坏了”，而是 asm contract 没有描述真实副作用。

---

### 一、常见错误清单

1. 修改 input-only operand，却没有使用 `+`。
2. 多 instruction template 提前覆盖 output，却没有 `&`。
3. 隐式修改 fixed register，却没有 output 或 clobber。
4. 访问 memory，却既没有 memory operand，也没有 `"memory"`。
5. 把 `volatile` 误认为 compiler memory barrier。
6. 只写 `"memory"`，却期待它生成 hardware fence。
7. 使用错误 C type，导致 XLEN、sign extension 或 register width 不匹配。
8. 改变 stack pointer 后没有在 asm 结束前恢复。
9. 在模板中执行 `call`，却没有完整表达 calling convention clobber。
10. 假设 compiler 会按源码顺序紧邻放置多个独立 asm statement。

若几条 instruction 必须不可分割，应放进同一个 asm template，并通过 operand 描述它们的
整体输入输出。

---

### 二、ABI 仍然有效

内联汇编位于 compiler 生成的函数内部，不是 ABI 真空区：

- compiler 可能在任意 caller-saved register 中保存 live value。
- callee-saved register 必须满足函数 ABI。
- stack alignment 必须保持。
- function call 会破坏 ABI 规定的 caller-saved state。

不要在 inline asm 中随意 `call symbol`。compiler 无法仅靠一个简单 clobber list 建模
完整调用，尤其是 memory、stack、TLS、PIC/PLT 和 unwind 行为。直接从 C 调用函数，或把
整段逻辑写成独立 assembly function。

---

### 三、逐层检查生成结果

保留 compiler 生成的 assembly：

```bash
riscv64-linux-gnu-gcc -march=rv32im_zicsr -mabi=ilp32 \
  -O2 -Wall -Wextra -S test.c -o test.s
```

检查 object：

```bash
riscv64-linux-gnu-gcc -march=rv32im_zicsr -mabi=ilp32 -O2 -c test.c
riscv64-linux-gnu-objdump -drS test.o
riscv64-linux-gnu-readelf -rWs test.o
```

重点观察：

- `%[name]` 最终分配到哪些 register。
- input 与 output 是否发生合法重叠。
- compiler 是否在 asm 前后插入 load/store。
- symbol reference 是否产生预期 relocation。
- instruction 是否因 `-march` 不匹配而报错。

---

### 四、必须测试优化组合

至少编译并运行：

```text
-O0
-O2
-O3 或 -Os
LTO enabled
GCC
Clang（若项目声称支持）
```

还应改变 register pressure，例如增加调用者 local variable、inline wrapper、循环和函数
调用。错误 constraint 往往只在 allocator 被迫选择某种重叠时暴露。

`volatile` 不是修复错误 constraint 的万能开关。它可能改变代码布局而暂时掩盖问题，
但不会自动补齐 input、output 或 clobber。

---

### 五、可移植 wrapper

把 target-specific asm 隔离在小型 `static inline` wrapper 中：

```c
#if defined(__riscv)
static inline void cpu_relax(void) {
  asm volatile("nop");
}
#else
#error "cpu_relax requires a supported target"
#endif
```

wrapper 应明确：需要的 ISA extension、privilege、memory-order semantics、输入宽度和是否
允许 compiler 重排。业务代码不应散落重复的 asm string。
