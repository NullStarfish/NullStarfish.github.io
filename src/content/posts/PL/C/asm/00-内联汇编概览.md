内联汇编允许在 C 函数中嵌入少量 assembly instruction。它适合表达编译器没有直接
接口的操作，例如访问 CSR、执行 `fence`、实现特殊原子指令或切换上下文。

它不适合替代普通 C 运算。编译器通常比手写汇编更擅长寄存器分配、指令调度和跨函数
优化。较长的汇编函数也更适合放在独立的 `.S` 文件中。

---

### 一、两种 GNU asm

Basic asm 只有汇编字符串：

```c
__asm__("nop");
```

Extended asm 还描述输入、输出和副作用：

```c
uint32_t add(uint32_t a, uint32_t b) {
  uint32_t result;
  __asm__("add %[dst], %[lhs], %[rhs]"
          : [dst] "=r"(result)
          : [lhs] "r"(a), [rhs] "r"(b));
  return result;
}
```

在函数内部应优先使用 extended asm。编译器不理解模板中 `add` 的语义；它只根据
operand constraint 得知：两个值被读取，一个值被写入。约束漏写，即使汇编文本看起来
正确，也可能在 `-O2` 下产生错误代码。

---

### 二、它经过哪些工具

```text
C source with asm
  -> compiler: 分配寄存器、替换 %0/%[name]
assembly output
  -> assembler: 编码指令、生成 relocation
object file
  -> linker: 解析 symbol、完成布局
```

内联汇编不是把机器码直接塞进 C 文件。模板最终仍由目标平台的 assembler 解析，因此
其中使用的是 GNU AS 的 RISC-V syntax、directive 和 relocation modifier。

查看编译器生成的汇编：

```bash
riscv64-linux-gnu-gcc -march=rv32im_zicsr -mabi=ilp32 \
  -O2 -S demo.c -o demo.s
```

查看最终机器码和 relocation：

```bash
riscv64-linux-gnu-gcc -march=rv32im_zicsr -mabi=ilp32 -O2 -c demo.c
riscv64-linux-gnu-objdump -dr demo.o
```

### 三、先选更高层的接口

使用内联汇编前依次考虑：

1. 普通 C 能否表达。
2. 标准库、C atomic 或 compiler builtin 是否已经提供接口。
3. 是否只有一小段 target-specific instruction 必须手写。
4. 是否已经长到应该放进独立 `.S` 文件。

Builtin 知道指令语义，通常比 opaque inline asm 更容易优化，也更容易被 sanitizer 和
静态分析工具理解。

---

### 四、GNU extension 与编译选项

`asm` 是 GNU extension。严格标准模式下可使用不会与用户标识符冲突的拼写：

```c
__asm__ __volatile__("fence rw, rw" ::: "memory");
```

常见编译模式：

```bash
gcc -std=gnu11 ...
gcc -std=c11 ...       # 使用 __asm__ 拼写
```

GCC 与 Clang 都支持大量 GNU extended asm 语法，但 target constraint 和部分
`asm goto` 能力仍应按编译器版本验证。
