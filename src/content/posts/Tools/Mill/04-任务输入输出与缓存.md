自定义 Mill 任务最容易出错的地方不是 Scala 语法，而是没有把真实输入和输出告诉
Mill。缓存正确性的原则是：**影响结果的量必须成为任务输入，生成文件应放进该任务的
专属输出目录。**

---

### 一、三类常用任务

```scala
// 文件或目录输入：内容变化会使下游失效
def rtlSources = Task.Sources("src/main/scala")

// 普通任务：可缓存，适合编译、生成文件和计算元数据
def sourceNames = Task {
  os.walk(rtlSources().single.path).map(_.last)
}

// 命令：可接收 CLI 参数，适合用户主动触发的操作
def emit(top: String) = Task.Command {
  println(s"emit $top")
}
```


---

### 二、`Task.dest` 是任务独占目录

```scala
def generatedSources = Task {
  val out = Task.dest / "Generated.scala"
  os.write(out, "object Generated { val width = 32 }", createFolders = true)
  Seq(PathRef(Task.dest))
}
```

`Task.dest` 的特点：

- 每个任务拥有不同目录。
- 普通任务重新计算前，Mill 会清理该目录。
- 可安全地作为编译器、代码生成器和文件复制的输出位置。
- 返回 `PathRef` 后，下游任务能够跟踪文件内容。

不要返回普通字符串路径来代表文件产物；字符串没有文件内容签名语义。

---

### 三、复制一组源文件

选择性编译模块常把真实工程中的部分源文件复制到隔离目录：

```scala
def selectedSources = Task.Sources(
  Task.workspace / "src/main/scala/mycpu/common/Config.scala",
  Task.workspace / "src/main/scala/mycpu/core/Alu.scala",
)

override def generatedSources = Task {
  val root = Task.workspace
  val dest = Task.dest / "src"

  for (ref <- selectedSources()) {
    val file = ref.path
    val out = dest / file.relativeTo(root)
    os.copy(file, out, createFolders = true)
  }

  Seq(PathRef(dest))
}
```

重点不是“复制”本身，而是 `selectedSources` 把文件内容登记为输入。若只在任务体里从
任意绝对路径读文件，Mill 未必知道该文件变化后应重新运行任务。

---

### 四、环境变量也必须显式建模

```scala
def verilatorRoot = Task.Input {
  Task.env.get("VERILATOR_ROOT")
}
```

任务通过 `Task.env` 读取环境变量后，变量增加、删除或改变都可以使依赖它的缓存正确
失效。不要在构建加载阶段把 `sys.env(...)` 保存为普通顶层值。

---

### 五、判断一次重新构建是否合理

```bash
mill show cpu.sources
mill inspect cpu.compile
mill cpu.compile
mill cpu.compile      # 没有输入变化时应复用缓存
```

若第二次仍执行，依次检查：任务是否为 command/uncached task、输入是否包含不稳定值、
是否写到了 `Task.dest` 之外、上游任务的返回值是否每次变化。
