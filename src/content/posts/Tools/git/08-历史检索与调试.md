Git 历史不仅用于回顾提交，也可以回答“哪次变化引入了这行代码”“一个字符串何时消失”
和“哪个提交首次让测试失败”。

---

### 一、定制 Log

```bash
git log --oneline --decorate --graph --all
git log --stat -10
git log -p -- path/to/file
git log --follow -- path/to/renamed-file
```

按作者和时间筛选：

```bash
git log --author='Alice' --since='2026-01-01' --until='2026-07-01'
```

`--follow` 只针对单个路径，并以相似度推断重命名；Git 不保存独立的“重命名对象”。

---

### 二、按内容变化搜索

搜索增加或删除指定字符串的提交：

```bash
git log -S'function_name' -p
```

搜索 diff 中匹配正则的提交：

```bash
git log -G'old_api\s*\(' -p
```

`-S` 关注字符串出现次数是否变化，`-G` 关注 patch 的新增或删除行是否匹配正则。

在当前版本或指定提交中搜索：

```bash
git grep 'TODO'
git grep 'CONFIG_FOO' v1.0.0
```

---

### 三、检查某行来源

```bash
git blame -L 40,70 path/to/file
git blame -w path/to/file
```

blame 显示最后修改每一行的提交，不等同于作者归责。格式化、移动代码和批量重构会影响
结果，应继续用 `git show COMMIT` 阅读上下文。

---

### 四、二分定位缺陷

已知当前版本失败、旧版本正常时：

```bash
git bisect start
git bisect bad HEAD
git bisect good v1.2.0
```

Git checkout 中间提交后运行测试，并标记：

```bash
git bisect good
git bisect bad
git bisect reset
```

测试可自动化时：

```bash
git bisect run ./scripts/regression-test.sh
```

脚本退出码 `0` 表示 good，`1-127`（除 `125`）表示 bad，`125` 表示当前提交无法测试并
跳过。测试必须稳定，否则二分结论不可靠。
