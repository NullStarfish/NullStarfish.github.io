远程仓库是其他 Git 仓库的地址。`origin/main` 不是服务器上的实时分支，而是本地记录的
“上次 fetch 后，远程 main 所在位置”。

---

### 一、管理 Remote

```bash
git remote -v
git remote show origin
git remote add origin git@example.com:user/project.git
git remote set-url origin NEW_URL
```

`origin` 只是 clone 时使用的默认名称，不具有特殊语义。开源协作中常把自己的 fork 叫
`origin`，把原仓库叫 `upstream`。

---

### 二、Fetch 只更新远程跟踪引用

```bash
git fetch origin
git fetch --all --prune
```

fetch 后先检查：

```bash
git log --oneline HEAD..origin/main
git diff HEAD..origin/main
git log --graph --oneline --decorate --all
```

确认后再合并或 rebase：

```bash
git merge --ff-only origin/main
# 或
git rebase origin/main
```

---

### 三、Pull 是组合操作

```bash
git pull --ff-only
git pull --rebase
```

`pull` 先 fetch，再按照配置 merge 或 rebase。建议明确策略，避免不同 Git 版本或个人
配置导致行为不一致：

```bash
git config --global pull.ff only
# 或者团队统一使用
git config --global pull.rebase true
```

---

### 四、Push 与 Upstream

首次推送本地分支：

```bash
git push -u origin feature/login
```

`-u` 建立 upstream，之后可以直接：

```bash
git push
git pull --ff-only
git branch -vv
```

删除远程分支：

```bash
git push origin --delete feature/login
```

---

### 五、拒绝 Non-fast-forward

如果远程包含本地没有的提交，普通 push 会被拒绝。先 fetch 并整合远程历史：

```bash
git fetch origin
git rebase origin/main
git push
```

确实需要更新自己刚刚 rebase 的远程分支时，使用带租约的强推：

```bash
git push --force-with-lease
```

`--force-with-lease` 会检查远程引用是否仍是预期值，比 `--force` 安全，但仍会重写共享
历史。不要对受保护分支或他人正在使用的分支随意强推。
