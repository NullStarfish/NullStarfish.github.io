Git 的日常操作可以理解为比较和移动三份状态：

| 状态 | 含义 | 常用查看方式 |
| :--- | :--- | :--- |
| `HEAD` | 当前提交保存的快照 | `git show HEAD` |
| index | 下一次提交的候选快照，也叫暂存区 | `git diff --cached` |
| working tree | 磁盘上正在编辑的文件 | `git diff` |

---

### 一、观察仓库状态

```bash
git status
git status --short
```

短格式中左列表示 index，右列表示工作区：

```text
 M note.md   # 工作区已修改，尚未暂存
M  main.c    # 修改已经暂存
MM both.c    # 暂存后又继续修改
?? new.txt   # 未跟踪文件
```

---

### 二、比较三份状态

```bash
git diff                 # 工作区 vs index
git diff --cached        # index vs HEAD
git diff HEAD            # 工作区 vs HEAD
git diff --stat HEAD
```

提交前同时检查 `git diff` 和 `git diff --cached`，可以避免漏提交或误提交。

---

### 三、将修改加入暂存区

```bash
git add README.md
git add src/
git add -u
git add -A
git add -p
```

- `-u` 暂存已跟踪文件的修改和删除，不加入新文件。
- `-A` 暂存仓库中的全部变化。
- `-p` 按 hunk 交互选择，适合把混在一起的修改拆成多个提交。

`git add` 复制的是执行命令那一刻的文件内容。暂存后继续编辑，新的修改不会自动进入
index。

---

### 四、创建提交

```bash
git commit
git commit -m "docs: explain the index"
git commit -v
```

一次提交应表达一个完整、可解释的变化。推荐使用祈使句描述“这个提交做什么”，并在
正文解释原因、约束和取舍，而不是逐行复述 diff。

修改最近一次提交：

```bash
git add forgotten-file.md
git commit --amend
```

`--amend` 会创建新提交并替换旧提交。已经推送且被他人使用的提交不要随意 amend。

---

### 五、查看提交结果

```bash
git show --stat HEAD
git show --name-status HEAD
git log --oneline --decorate -5
```

提交完成后工作区不一定干净，因为未暂存的修改仍会保留：

```bash
git status --short
```
