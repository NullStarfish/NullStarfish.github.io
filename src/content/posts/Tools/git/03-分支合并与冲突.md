分支是指向提交的可移动引用。推荐使用 `git switch` 切换分支，使用 `git restore` 恢复
文件；旧式 `git checkout` 同时承担两种职责，容易混淆。

---

### 一、创建和切换分支

```bash
git branch
git switch -c feature/login
git switch main
git branch -d feature/login
```

基于指定提交创建：

```bash
git switch -c hotfix v1.2.0
```

`-d` 只删除已经合并的分支；`-D` 强制删除引用，使用前应确认提交仍可通过其他引用找到。

---

### 二、Fast-forward 与 Merge Commit

如果 `main` 没有新提交，合并可以直接移动引用：

```bash
git switch main
git merge feature/login
```

需要明确保留分支边界时：

```bash
git merge --no-ff feature/login
```

禁止意外产生 merge commit：

```bash
git merge --ff-only origin/main
```

---

### 三、三方合并

历史已经分叉时，Git 使用共同祖先、当前分支 tip 和待合并分支 tip 做三方合并。不同
文件或同一文件不同区域的修改通常能自动合并；无法判断意图时会留下冲突。

```bash
git status
git diff --name-only --diff-filter=U
```

冲突文件中可能出现：

```text
<<<<<<< HEAD
current branch
=======
incoming branch
>>>>>>> feature/login
```

编辑为最终结果后标记已解决：

```bash
git add path/to/file
git commit
```

放弃整个合并：

```bash
git merge --abort
```

---

### 四、检查合并前后的历史

```bash
git log --graph --oneline --decorate --all
git diff main...feature/login
git log main..feature/login
```

`main...feature/login` 用 merge base 与 feature 比较，适合查看一个分支相对起点引入的
完整变化。

---

### 五、常见原则

- 开始合并前先提交或 stash 当前工作。
- 冲突解决的是代码意图，不是机械删除冲突标记。
- 解决后运行测试并重新检查 diff。
- 不要把生成文件、依赖目录和编辑器缓存纳入无意义的冲突。
