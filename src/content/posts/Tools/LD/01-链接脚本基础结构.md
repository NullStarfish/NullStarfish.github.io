每一次链接都会受到链接脚本控制。没有显式指定脚本时，ld 使用内建默认脚本；使用
`-T link.ld` 后，自定义脚本成为主链接脚本。

链接脚本是由命令、符号赋值和表达式组成的文本文件。注释采用 C 风格：

```ld
/* This is a linker script comment. */
```

---

### 一、最小裸机脚本

```ld
OUTPUT_ARCH(riscv)
ENTRY(_start)

SECTIONS
{
  . = 0x80000000;

  .text : {
    KEEP(*(.text.entry))
    *(.text .text.*)
  }

  .rodata : {
    *(.rodata .rodata.*)
  }

  .data : {
    *(.data .data.*)
  }

  .bss (NOLOAD) : {
    *(.bss .bss.*)
    *(COMMON)
  }
}
```

链接：

```bash
riscv64-linux-gnu-ld -m elf32lriscv -T link.ld \
  -o app.elf start.o main.o
```

### 二、输入段和输出段

编译器在每个 `.o` 中生成输入段，例如：

```text
.text
.text.main
.rodata.str1.4
.data
.bss
```

脚本左侧定义输出段，花括号内部选择输入段：

```ld
.text : {
  *(.text .text.*)
}
```

含义是：把所有输入文件 `*` 中名为 `.text` 或匹配 `.text.*` 的输入段，合并到
输出 ELF 的 `.text` 输出段。

输入段和输出段可以同名，但它们不是同一个概念。

---

### 三、位置计数器 `.`

特殊符号 `.` 表示当前位置：

```ld
. = 0x80000000;
```

它把后续输出段的起始位置移动到 `0x80000000`。输出段写入内容时，`.` 会自动向前
增长。

```ld
.text : {
  _text_start = .;
  *(.text .text.*)
  _text_end = .;
}
```

这里 `_text_start` 和 `_text_end` 是提供给程序使用的 linker symbol，不会占用额外
存储空间。

---

### 四、入口地址

```ld
ENTRY(_start)
```

它设置 ELF header 中的 entry point。`_start` 必须由某个输入文件定义，例如：

```asm
.section .text.entry
.globl _start
_start:
  /* initialize stack and runtime */
```

`ENTRY` 不会自动把 `_start` 移动到第一个地址，所以通常还要显式放置 `.text.entry`。
在启用 `--gc-sections` 时，`KEEP` 可以防止入口段被删除。

---

### 五、Orphan Section

输入文件中存在、但脚本没有匹配的输入段称为 orphan section。ld 默认会尝试把它
放到属性相近的输出段附近，而不是直接报错。

这可能让新增加的段悄悄进入意外位置。严格检查时可以使用：

```bash
ld --orphan-handling=warn ...
ld --orphan-handling=error ...
```

也应检查 map 文件和：

```bash
readelf -S app.elf
```
