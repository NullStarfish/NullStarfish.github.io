`ld` 是 GNU Binutils 中的链接器。编译器把源文件变成可重定位目标文件后，链接器负责：

1. 收集目标文件和静态库中的输入段。
2. 解析全局符号和未定义符号。
3. 决定各段在输出文件及内存中的地址。
4. 根据最终地址应用 relocation。
5. 生成 ELF 可执行文件、共享库或另一个可重定位文件。

链接脚本的核心任务，就是控制第 3 步的内存布局。

---

### 一、从源码到 ELF

```bash
riscv64-linux-gnu-gcc -march=rv32e -mabi=ilp32e \
  -ffreestanding -ffunction-sections -fdata-sections \
  -c start.S main.c

riscv64-linux-gnu-ld -m elf32lriscv \
  -T link.ld \
  --gc-sections \
  -Map=app.map \
  -o app.elf start.o main.o
```

常见输入包括：

- `.o`：可重定位目标文件。
- `.a`：由多个 `.o` 组成的静态 archive。
- `.so`：共享库，主要用于有动态加载器的系统。
- `.ld`：链接脚本。

---

### 二、直接调用 ld 与通过 GCC 调用

裸机工程可以直接调用 `ld`，但通常更推荐让 GCC driver 完成链接：

```bash
riscv64-linux-gnu-gcc \
  -march=rv32e -mabi=ilp32e \
  -nostdlib -nostartfiles \
  -T link.ld \
  -Wl,--gc-sections \
  -Wl,-Map=app.map \
  -o app.elf start.o main.o
```

GCC 能自动选择正确的 linker emulation、ABI 和运行库。传给 `ld` 的参数使用：

```text
-Wl,参数1,参数2
```

例如：

```bash
-Wl,-Map=app.map,--gc-sections,--print-memory-usage
```

`-T link.ld` 是 GCC 和 ld 都能识别的常见写法。

---

### 三、常用选项

| 选项 | 作用 |
| :--- | :--- |
| `-o FILE` | 指定输出文件。 |
| `-T SCRIPT` | 使用自定义链接脚本，并取代默认主脚本。 |
| `-e SYMBOL` | 指定入口符号，优先级高于脚本中的 `ENTRY`。 |
| `-L DIR` | 添加静态库和共享库搜索目录。 |
| `-lNAME` | 搜索 `libNAME.a` 或 `libNAME.so`。 |
| `-Map=FILE` | 输出完整 link map。 |
| `--gc-sections` | 删除不可达的输入段。 |
| `--print-gc-sections` | 显示被 GC 删除的段。 |
| `--print-memory-usage` | 按 `MEMORY` region 显示使用量。 |
| `--trace` | 显示 linker 实际读取的输入文件。 |
| `--trace-symbol=NAME` | 显示哪些文件定义或引用指定符号。 |
| `-r` | 进行 partial link，输出仍是可重定位文件。 |

### 四、静态库的顺序

静态库通常按命令行从左到右扫描：

```bash
ld main.o -lfoo -lbar
```

如果 `libfoo.a` 需要 `libbar.a`，这个顺序通常正确；反过来可能产生 undefined
reference。循环依赖可以使用 group：

```bash
ld main.o --start-group -lfoo -lbar --end-group
```

通过 GCC driver 时写成：

```bash
gcc main.o -Wl,--start-group -lfoo -lbar -Wl,--end-group
```

---

### 五、默认链接脚本

即使没有传入 `-T`，ld 也会使用内部默认脚本。可以查看它：

```bash
ld --verbose
riscv64-linux-gnu-ld --verbose
```

交叉链接器的默认脚本和宿主机 ld 不同。分析一个工程时，应使用实际参与构建的
toolchain 查询。
