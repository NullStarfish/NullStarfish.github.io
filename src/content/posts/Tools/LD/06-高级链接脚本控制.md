大多数裸机脚本只需要 `MEMORY` 和 `SECTIONS`。本篇收集控制 ELF 格式、程序头、默认
输入和输出段属性的高级命令。

---

### 一、目标格式与体系结构

```ld
OUTPUT_ARCH(riscv)
OUTPUT_FORMAT("elf32-littleriscv")
ENTRY(_start)
```

- `OUTPUT_ARCH` 指定输出 machine architecture。
- `OUTPUT_FORMAT` 指定 BFD 输出格式。
- `ENTRY` 指定 ELF entry point。

除非确实需要固定格式，否则交叉 GCC/ld 通常已经能正确选择它们。

---

### 二、默认输入文件和库

```ld
STARTUP(start.o)
INPUT(runtime.o)
GROUP(-lc -lgcc)
INCLUDE memory.ld
```

- `STARTUP` 类似 `INPUT`，但将文件放在输入列表开头。
- `INPUT` 无条件加入文件或库。
- `GROUP` 反复搜索其中的 archive，处理循环符号依赖。
- `INCLUDE` 引入另一个链接脚本。

把所有输入都藏进脚本会降低构建系统可见性。一般只把固定平台组件放进脚本，普通
对象文件仍由 Make/Ninja 命令行传入。

---

### 三、Program Header 与 `PHDRS`

Section 描述链接视角的代码和数据分类；ELF program header 描述 loader 应如何装载
segment。多个 section 可以属于同一个 `PT_LOAD` segment。

```ld
PHDRS
{
  text PT_LOAD FLAGS(5); /* R + X */
  data PT_LOAD FLAGS(6); /* R + W */
}

SECTIONS
{
  .text : { *(.text .text.*) } :text
  .rodata : { *(.rodata .rodata.*) } :text
  .data : { *(.data .data.*) } :data
  .bss (NOLOAD) : { *(.bss .bss.*) } :data
}
```

一旦脚本提供 `PHDRS`，ld 不再自动创建其他 program header，因此漏配可能使 loader
无法正确装载 ELF。裸机 binary-only 流程通常不需要手写它。

---

### 四、输出段类型和属性

```ld
.bss (NOLOAD) : { *(.bss .bss.*) } > RAM
.metadata 0 (INFO) : { *(.metadata) }
```

常见类型：

- `NOLOAD`：运行时占空间，但不要求装载文件内容。
- `INFO`：生成非 allocatable section。
- `/DISCARD/`：丢弃匹配的输入段。

输出段还可以使用：

```ld
.text : ALIGN(16) { ... }
.table : SUBALIGN(4) { ... }
```

`SUBALIGN` 强制内部输入段使用指定 alignment，可能覆盖输入段原始要求，使用时要确认
数据访问约束。

---

### 五、填充与显式数据

在输出段中写入常量：

```ld
.header : {
  LONG(0x12345678)
  SHORT(0xabcd)
  BYTE(0xef)
}
```

设置未占用字节的填充值：

```ld
.text : {
  *(.text .text.*)
  FILL(0x00000013)
  . = ALIGN(16);
} = 0xff
```

段尾的 `=fill` 和段内 `FILL(expression)` 都能控制空洞填充，但单位和目标端序应通过
最终 binary 检查。

---

### 六、Overlay

多个模块在不同时间运行、但共享同一块运行内存时，可以使用 `OVERLAY`：

```ld
OVERLAY 0x80010000 : AT(0x30010000)
{
  .task_a { task_a.o(.text .data) }
  .task_b { task_b.o(.text .data) }
}
```

各成员拥有相同或连续约束的 VMA，但 LMA 不同。运行时必须由软件负责把需要的模块
搬入共享区域。普通固件不需要使用它。
