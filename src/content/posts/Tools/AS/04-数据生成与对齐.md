Assembler directive 不一定只修改 metadata。许多 directive 会在当前 section 中直接
生成字节、字符串、地址或填充空间。

---

### 一、生成整数

```asm
.byte  0x12
.2byte 0x3456
.4byte 0x789abcde
.8byte 0x1122334455667788
```

常见别名包括：

```asm
.half  0x1234
.word  0x12345678
.dword 0x1122334455667788
```

不同 target 对某些传统名字的宽度可能存在差异。跨架构脚本优先使用明确宽度的
`.2byte`、`.4byte` 和 `.8byte`，并通过 `readelf`/`objdump` 验证端序。

表达式可以包含 symbol：

```asm
.word handler
.word table_end - table_start
```

如果 assembler 不知道 `handler` 的最终地址，会生成 relocation，而不是随便填一个
最终地址。

---

### 二、字符串

```asm
.ascii "hello"
.asciz "hello"
.string "hello"
```

- `.ascii` 不自动添加结尾 `\0`。
- `.asciz` 添加一个结尾 `\0`。
- `.string` 在常见 GAS target 上也会为每个字符串添加结尾零。

多个字符串：

```asm
.ascii "hello", "world"
```

转义规则类似 C string，例如 `\n`、`\t`、`\\` 和 `\"`。

---

### 三、保留或填充空间

```asm
.space 64
.space 64, 0xff
.skip 32
.zero 128
```

- `.space size, fill` 生成指定数量的填充 byte。
- `.skip` 通常是 `.space` 的同义形式。
- `.zero size` 生成指定数量的零。

在 `@nobits` section 中，这些 directive 通常只增加 section size，不会在 `.o` 中保存
对应数量的零字节。

重复生成固定元素：

```asm
.fill 16, 4, 0xdeadbeef
```

表示生成 16 个元素，每个元素 4 byte，值为 `0xdeadbeef`。

---

### 四、Alignment

推荐使用语义明确的：

```asm
.balign 16
.p2align 4
```

两者都对齐到 16-byte：

- `.balign 16` 的参数直接是 byte alignment。
- `.p2align 4` 的参数是 2 的指数，即 `2^4`。

指定填充值和最大跳过量：

```asm
.balign 16, 0, 15
.p2align 4, 0, 15
```

第三个参数表示为实现 alignment 最多允许跳过多少 byte；超过时不进行对齐。

`.align` 的参数语义在不同 architecture 上可能表示 byte 数，也可能表示 2 的指数。
跨平台代码应优先使用 `.balign` 或 `.p2align`。

---

### 五、Code Section 的填充

```asm
.text
.p2align 4
```

当 code section 没有显式 fill value 时，GAS 通常会使用目标架构适合的 NOP 填充，而不
是简单写零。显式指定填充值可能产生不可执行编码，应谨慎。

---

### 六、`.org` 为什么要谨慎

```asm
.org 0x100
```

`.org` 只移动当前 section 内部的 location counter，并不能可靠地指定 section 最终
运行地址。最终 VMA 应由 linker script 决定。

Assembler 通常也不允许 `.org` 向后移动。需要硬件内存布局时，应使用 LD 的
`MEMORY`、`SECTIONS` 和输出段地址，而不是在 `.s` 中堆叠 `.org`。

---

### 七、检查生成结果

```bash
riscv64-linux-gnu-objdump -s file.o
riscv64-linux-gnu-objdump -h file.o
riscv64-linux-gnu-readelf -x .rodata file.o
```
